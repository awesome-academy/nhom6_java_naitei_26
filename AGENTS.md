
# Project Instructions

Before making any changes to this repository, read and follow the project guidelines below.

## Business Rules

Before implementing, modifying, or fixing any feature:

- Read `docs/database/DATABASE_DESIGN.md`.
- Carefully understand the business rules related to the feature being worked on.
- Do not implement a feature based only on assumptions.
- The implementation must follow the documented business logic and database design.
- If the requested implementation conflicts with the documented business rules, report the conflict before making changes.

## Git Workflow

Before starting development:

- Read `docs/conventions_and_workflow/workflow-in-sun.md`.

Before creating a commit:

- Read and follow `docs/conventions_and_workflow/github-commit-convention.md`.

Before creating or updating a Pull Request:

- Read `docs/conventions_and_workflow/pull-request-guide.md`.
- Follow `.github/pull_request_template.md`.

## Required Rules

- Do not invent project conventions.
- Do not invent business rules.
- Always understand the relevant business logic before implementing a feature.
- Follow the documented Git workflow.
- Follow the documented commit convention.
- Follow the Pull Request guide when creating or updating a Pull Request.
- If documentation conflicts with assumptions, the documentation takes priority.
